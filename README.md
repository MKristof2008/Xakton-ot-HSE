# Ревизор

Фактчекинг по замыслу эксперта NMH: **бесплатно — вердикт, по подписке — разбор**.

## Что это

Вставляешь сообщение из чата или пересылки — получаешь ответ: правда, фейк или
непонятно. Бесплатно видно только вердикт и уровень доверия. По подписке
открывается разбор: почему такой вердикт, по каждому сигналу, со ссылками на
первоисточники.

Проверить можно четырьмя способами:

| Вход | Что делает |
|---|---|
| **Текст** | извлечение утверждений, сверка с базой, поиск источников |
| **Ссылка** | скачивает страницу и проверяет её как источник |
| **Скриншот** | метаданные файла, следы генерации и монтажа, контекст публикации |
| **Видео** | метаданные контейнера, следы генератора, статичность кадров |

Скриншот, видео и ссылка — это те материалы, которые реально присылают в
мессенджере.

Вторая вкладка — **топы проверок**. Одинаковые сообщения схлопываются в одну
строку, чем больше людей проверило — тем выше. Из этого рейтинга вырастает медиа,
которое публикует только проверенное.

## Как система думает

Вердикт — не «мнение модели». Он собирается по рубрике из шести критериев, и
каждый балл объяснён словами:

| Критерий | Максимум | Что оценивает |
|---|---|---|
| Основание | 30 | есть ли дословная цитата, проверенная кодом |
| Согласие источников | 20 | все подтверждают / опровергают или расходятся |
| Надёжность | 15 | официальный домен или неизвестный блог |
| Полнота | 15 | сколько утверждений удалось проверить |
| Противоречие | 10 | не спорят ли утверждения между собой |
| Готовое знание | 10 | было ли уже проверено раньше |

Перед проверкой утверждение относится к **теме** (деньги, законы, здоровье,
происшествия, армия и т. д.). У темы свои правила: например, экономика
проверяется по официальным источникам, а прогноз нельзя объявить ложью.
Разметка детерминированная — без модели, чтобы вердикт не «плавал» между
прогонами.

Проверенные утверждения с источником попадают в **банк знаний**
(`ml/lakmus/data/knowledge_bank.json`). Следующая такая же проверка
отвечает из банка — быстрее и стабильнее.

## Почему это нужно NMH

- Готовая аудитория и площадки для дистрибуции.
- Репутация источника проверенных новостей — актив, который нельзя скопировать кодом.
- Топы проверок = контент, который производит сама аудитория.

## Как работает

```
текст → сигналы проверки → слияние (субъективная логика) → вердикт
                                  ↓
                    free: вердикт · pro: разбор
```

Сигналы (6 штук, работают без модели):
`claims` · `kb_facts` · `sources` · `quotes` · `rhetoric` · `machine_text`

Ключевой — **`kb_facts`**: сверка с курируемой базой фактов
(`ml/lakmus/data/kb_facts.json`). Сравнивает числа и годы детерминированно:
«ставка 15%» не пройдёт, если в базе 21%. Чего нет в базе — говорит
«не проверено», а не «фейк».

## Запуск

```bash
# тесты, ключ не нужен
python -m pytest -q

# сервер
python -m uvicorn backend.main:app --port 8000

# интерфейс
cd frontend && npm install && npm run dev
```

Интерфейс проксирует `/api` на `localhost:8000` (см. `frontend/vite.config.ts`).
Второй вариант — собрать фронт (`npm run build`) и открыть `http://localhost:8000`:
FastAPI сам отдаст `frontend/dist`.

## Тарифы

| Тариф | Цена | Что даёт |
|---|---|---|
| База (free) | 0 ₽ | 10 проверок в день, вердикт и тема |
| Плюс (pro) | 300 ₽/мес | без лимита, рубрика, цитаты, «что делать» |
| Макс (team) | 5 000 ₽/мес | всё из «Плюса» + готовый текст для пересылки, ключи API |

**Вердикт одинаков на всех тарифах.** Разница — в объёме объяснения, как и
просил эксперт NMH: качество ответа не зависит от оплаты, платно открывается
разбор. Модель на каждый уровень можно задать отдельно через
`LLM_MODEL_BASE` / `LLM_MODEL_PLUS` / `LLM_MODEL_MAX`; если переменные не
заданы, все уровни работают на общей `LLM_MODEL`.

Первый месяц бесплатно: сначала репутация, потом подписка.

## Что не работает честно

- **Оплата — симулятор.** Платёж создаётся и подтверждается в нашей же базе,
  реального списания нет. В интерфейсе это написано.
- **Скриншоты проверяются по метаданным и следам монтажа**, а не «пониманием»
  картинки. Текст со скриншота читается только при установленном OCR
  (`pytesseract` или `paddleocr`) — без него сигнал честно отвечает «нет данных».
- **База фактов маленькая** — 19 тем, по одному факту в каждой. Это демонстрация
  механики, а не полноценный фактчек. Чего нет в базе — помечается «не проверили».
- **Поиск по интернету нужен ключ.** `SERPER_API_KEY`: без него сигналы `sources`
  и `quotes` возвращают «нет данных», и проверка идёт только по базе фактов.
- **Модель нужна для умной проверки.** `LLM_API_KEY`: без ключа пайплайн работает
  детерминированно, но не извлекает утверждения из свободного текста.
- **Точность на своём наборе — 20/28 без ключей.** С ключами выше; цифра
  пересчитывается прогоном `python -I ml/tools/eval_run.py`.
- Топы считаются за последние 48 часов и живут в SQLite на одном сервере.

## Проверка живьём

```bash
# все входы через настоящий API: текст, ссылка, фото, видео, три тарифа
node frontend/live_inputs.mjs

# рубрика: тема, критерии, баллы по каждому пункту
node frontend/live_reasoning.mjs

# три тарифа на одном тексте: вердикт совпадает, разбор растёт
py -3 -I ml/tools/live_tiers.py

# какие модели реально отвечают на ключе
py -3 -I ml/tools/probe_models.py
```

Тестов сейчас **350**, прогон занимает ~6 секунд и не ходит в сеть.

## Как принимается вердикт

Модель не решает «на глаз». Порядок такой:

1. **Тема** — утверждение относится к классу (деньги, законы, здоровье,
   происшествия, армия, политика, технологии, транспорт, звёзды, погода).
2. **Плейбук** — под тему и тип материала выдаётся чек-лист: что проверить,
   какие признаки говорят о подделке, какие о подлинности и что
   доказательством **не** считается.
3. **Правила** — признаки сводятся в вердикт по явным правилам с весами.
   Сильный признак решает сам, слабые не перебивают сильные, противоречие
   ведёт к «непонятно».
4. **Проверка кодом** — цитата обязана дословно найтись в источнике.
5. **Обучение** — поправка человека уходит в банк знаний и меняет
   следующий ответ; модель её не перетирает.

Файлы: `ml/lakmus/tags.py` · `playbook.py` · `verdict_rules.py` ·
`reasoning.py` · `bank.py`.
