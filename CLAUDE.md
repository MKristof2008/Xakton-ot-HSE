# «Свидетель» — продукт и правила работы

> Этот файл читают все: люди и AI-агенты. Если ты агент — прочитай его целиком
> до первого изменения файла.

## Что мы делаем

**Свидетель** — маркетплейс достоверного пользовательского контента для
News Media Holding (NMH) × МГТУ им. Баумана, AI Challenge, 13–15 ноября 2026.

Любой человек снимает фото или видео события и загружает его. Система
проверяет подлинность и оригинальность, оценивает материал и выставляет цену.
Редакции покупают материал. Автор получает деньги.

**Продукт продаёт не проверку, а доступ к свидетельствам.** Проверка — это
инфраструктура, без неё маркетплейс развалится, но клиенту её не продают.

### Почему это нужно именно NMH

- 260 площадок = готовые покупатели контента. Без покупателей маркетплейс мёртв.
- Mash / SHOT / Baza = туда очевидцы пишут первыми, это воронка поставщиков.
- Gigarama уже продавала материалы мировым СМИ (Нотр-Дам, CNN/BBC/NYT) — канал сбыта существует.
- Паблистер = B2B-клиенты, которым тоже нужны подлинные материалы.

### Чего мы НЕ делаем

- Не персональную ленту, не дайджест, не AI-пересказчик, не чат-бот по новостям
  (организатор исключил прямо).
- Не ещё один фактчекер. Лапша, Проверено.Медиа, «Война с фейками» уже есть и
  раздают проверку бесплатно. Проверка у нас — не продукт.
- Не обёртку над готовой моделью. Если убрать AI, продукт теряет смысл.

## Роль AI и почему ключ LLM не нужен

Пайплайн детерминированный. Модель нужна для извлечения утверждений и
сравнения текстов, но **ядро работает без неё**:

| Задача | Чем решается | Нужен ли LLM |
|---|---|---|
| Подлинность файла | EXIF / PNG-чанки / C2PA-манифест | нет |
| Следы генерации | ансамбль детекторов, метаданные | нет |
| Скриншот или фото | эвристики интерфейса | нет |
| Оригинальность | перцептивный хеш + дедуп по архиву | нет |
| Цена материала | правила по редкости, свежести, геолокации | нет |
| Разбор текста | claims / quotes / rhetoric | да, опционально |

Если LLM недоступен — система работает и честно помечает сигналы `unavailable`.
Это фича, а не баг: на защите демо не падает.

## Контракт (заморожен)

`contracts/check_result.schema.json` — единственный источник истины для обмена
между ML, backend и frontend.

**Правила:**
- Никто не меняет контракт без общего согласия. Меняешь — меняешь схему,
  Pydantic-модели в `ml/lakmus/schemas.py`, и уведомляешь остальных.
- ML отдаёт только `CheckResult`. Backend его не переписывает, а оборачивает.
- Frontend не парсит внутренности ML, только контракт.

## Зоны ответственности

**Один файл — один хозяин.** Не редактируй файлы чужой зоны. Нужно изменение —
пиши владельцу.

| Зона | Каталоги | Кто |
|---|---|---|
| ML / сигналы / пайплайн | `ml/lakmus/**`, `ml/tests/**`, `ml/tools/**` | агент 1 |
| Backend / API / хранилище | `backend/**`, `contracts/**` | агент 2 |
| Frontend | `frontend/**` | агент 3 |
| Демо-данные / e2e / документация | `ml/data/**`, `docs/**`, `*.md`, `demo/**` | агент 4 |

`README.md` в корне — общий, правки только через агента 4.

## Правила, которые нельзя нарушать

1. **Никаких фейков в демо.** Если функция не работает — она помечена как
   неработающая. Никаких `random.randint`, никаких заглушек, выдающих себя за
   результат.
2. **Секреты только из окружения.** `.env` в git не попадает. Ключи в коде,
   в тестах, в фикстурах — запрещено.
3. **Ошибки обрабатываются.** Отсутствие данных, сбой зависимости, мусорный
   ввод — это штатные ситуации, а не падение.
4. **Тесты зелёные перед коммитом.** `python -m pytest -q` из корня.
5. **Честные метрики.** Не писать «работает отлично», если проверено на трёх
   примерах. Указывать, на чём проверено и где проваливается.

## Команды

```bash
cd ml && python -m ml.lakmus.live --text "..."   # живой прогон (если есть ключ)
```
