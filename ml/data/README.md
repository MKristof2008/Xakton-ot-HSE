# Манифест тестового набора

Разметка по ТЗ 6.7: один объект — одна строка JSONL. Файлы образцов в git
не хранятся, `path` — путь-заглушка внутри `data/samples/…`; манифест
описывает, что за объект, даже если самого файла рядом нет.

## Поля строки

| поле | тип | смысл |
| --- | --- | --- |
| `id` | строка | Уникальный id объекта; по нему результаты прогона склеиваются с разметкой (`ml/data/results_example.jsonl`) |
| `path` | строка | Путь к образцу от корня репозитория, `data/samples/…` |
| `kind` | `image` \| `text` | Тип входа |
| `category` | `real_photo` \| `generated` \| `edited` \| `mislabelled` \| `text` | Категория ТЗ 6.7 |
| `label` | `real` \| `fake` \| `edited` \| `mislabelled` | Эталонный ответ |
| `generator` | строка или `null` | Для `generated`/машинных текстов: чем сделано |
| `source` | строка или `null` | Откуда объект: домен, архив, номер поста |

## Минимумы ТЗ

`real_photo` — 50, `generated` — 50, `edited` — 30, `mislabelled` — 20,
`text` — 60; всего не меньше 150 объектов. `lakmus.dataset.validate_dataset`
проверяет и общий объём, и каждый минимум.

## Бинарная метка

`real` → 1 (настоящее), `fake`/`edited`/`mislabelled` → 0: в вопросе
«можно ли пересылать как есть» правка и ложная подпись — не настоящее.

## Примеры

- `labels_example.jsonl` — 14 строк-заглушек, по одной-две на каждую
  категорию; это формат, а не рабочий набор (минимумы не набраны, поэтому
  `validate_dataset` выдаст предупреждения — так и должно быть).
- `results_example.jsonl` — 8 результатов прогона: `id`, `label`, `score`
  (0..100), `uncertainty` (0..1), `level`. Нужен, чтобы `ml/tools/eval.py`
  запускался без вызова модели.
- `demo/` — предрасчитанные `CheckResult` для demo-режима
  (`lakmus.demo`), файл на проверку: `demo_text_001.json`, `demo_image_001.json`.
