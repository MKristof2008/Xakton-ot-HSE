# Контракты ML ↔ backend ↔ frontend

`check_result.schema.json` — JSON Schema результата проверки (`CheckResult`).
Это единственный файл в каталоге, который читают другие команды.

## Правило одно: схема не правится руками

Файл генерируется из модели `ml/lakmus/schemas.py`, поэтому любая ручная
правка будет затёрта при следующей генерации:

```bash
.venv/Scripts/python.exe ml/tools/export_schema.py
```

Скрипт пишет `contracts/check_result.schema.json` из `CheckResult.model_json_schema()`
и печатает число свойств верхнего уровня.

## Как менять поля

Поля контракта — общая граница трёх команд (ТЗ, раздел 3). Поэтому:

1. изменение обсуждается на общем созвоне и фиксируется в задаче;
2. сначала правится `ml/lakmus/schemas.py` (pydantic-модель — источник истины);
3. затем перегенерируется схема командой выше и **коммитится вместе с моделью**
   в одном изменении — иначе backend и frontend разъедутся с ML;
4. договорённости по совместимости: новые поля добавляются с значениями
   по умолчанию, существующие не переименовываются и не удаляются без
   одновременной правки потребителей.

Проверить, что схема не отстала от модели, можно повторной генерацией:
после неё `git diff contracts/check_result.schema.json` должен быть пустым.
